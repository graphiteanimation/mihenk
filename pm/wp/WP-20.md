## İş
1. `.github/workflows/ci.yml`: `push` (master, wp-**) ve `workflow_dispatch`. Koşucu `windows-latest`, Node 22, Python 3 + `playwright` (chromium). Adımlar: `npm ci` → `npm run test:all` (python komutu Windows'ta `python`; gerekiyorsa platformdan bağımsız bir `scripts/test-all.mjs` koşucusu yaz, `test:all` onu çağırsın, Linux'ta da aynı sıra çalışsın) → `npm run dist` → kurulumu sessiz kur → kurulu exe'ye karşı Electron testleri (aç, kaydet, NC/DXF kaydet) → kurulum + SHA-256 `actions/upload-artifact` ile yüklenir (yalnız master'da 30 gün, dallarda 5 gün).
2. Kararsız olduğu bilinen `app.test.py` "konsolda sayfa hatası yok" kontrolü WP-04'ün işidir: testi değiştirme; CI'da test zincirini adım adım raporla ki hangi dosyanın kaldığı görünsün. Bu tek bilinen kararsızlık için en çok 1 yeniden deneme koyabilirsin (açıkça "bilinen kararsız, WP-04" etiketiyle).
3. `v*` etiketi itildiğinde aynı iş + GitHub Release'e kurulum ve SHA-256 ekleyen `release.yml` (ya da aynı dosyada koşullu iş).
4. Linux'ta doğrula: `npm run test:all` yeni koşucuyla yerelde baştan sona (sonuç sayılarıyla). Windows adımları yerelde koşulamaz; `gh run list/view/watch` ile dal itildikten sonra Actions sonucunu izle ve kırmızıysa günlükten düzelt (en çok 4 tur).
